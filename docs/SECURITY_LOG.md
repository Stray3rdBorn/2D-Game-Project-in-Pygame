# Security log

Updated whenever the project changes. Part A is done. Part B is not done yet, with a verdict on whether it is possible and necessary for this project (a hobby game with no money or private data at stake). Since the server is public, so open items weigh more than before.

## Part A: Covered

| Issue                                                                  | How it is covered                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API key visible on a web page and copied by hand                       | Removed. Login now returns a token that the game stores itself. The key table is dropped by a migration.                                                                                                                                                                                                                    |
| Passwords stored in plain text                                         | Django stores only a salted PBKDF2 hash. The game never saves the password.                                                                                                                                                                                                                                                 |
| Forged tokens                                                          | Tokens are signed (HS256) with `JWT_SECRET`. FastAPI accepts only HS256, so the "pick a weaker algorithm" trick fails. Wrong signature, garbage and expired tokens all give 401 (tested).                                                                                                                                   |
| Stolen token works forever                                             | Tokens expire after exactly 1 day (tested: `exp` minus `iat` is 86400 seconds).                                                                                                                                                                                                                                             |
| Weak passwords                                                         | Django's four password rules (length, not common, not all digits, not like the username) run on register.                                                                                                                                                                                                                   |
| Telling an attacker which half of a login was wrong                    | One message for wrong name and wrong password.                                                                                                                                                                                                                                                                              |
| Cross site request forgery (CSRF) on the JSON endpoints                | The two endpoints are exempt on purpose. They use no cookies, so there is nothing for a forged page to ride on. The admin page keeps CSRF protection.                                                                                                                                                                       |
| Secrets on GitHub                                                      | Secrets live only in `.env` (ignored by git). `.env.example` has placeholders. `JWT_SECRET` and `SECRET_KEY` are separate. CI uses dev only values.                                                                                                                                                                         |
| Bad or absurd scores                                                   | Server checks score 0 to 100000 and wave 1 to 10 (422 otherwise).                                                                                                                                                                                                                                                           |
| SQL injection                                                          | All database access goes through SQLAlchemy and Django, which send values separately from the query.                                                                                                                                                                                                                        |
| Leaderboard dies when Redis dies                                       | Falls back to PostgreSQL and rebuilds Redis when it is empty (tested).                                                                                                                                                                                                                                                      |
| Password or token sent in the open                                     | The game refuses any server address that is not `https`, except `localhost` and `127.0.0.1` (tested, including the trick address `localhost.evil.com`).                                                                                                                                                                     |
| Redirect leaking credentials                                           | Redirects are never followed.                                                                                                                                                                                                                                                                                               |
| Token file damage or tampering                                         | Atomic write (temporary file then swap), owner only permission on Linux and Mac, corrupted or wrong shape file counts as logged out, expired token deleted on load. A tampered file only causes a 401.                                                                                                                      |
| Raw server text shown on screen                                        | Only plain string messages are shown, everything else becomes "Server error".                                                                                                                                                                                                                                               |
| Huge or control character input                                        | Text boxes cap length (20 for new usernames, 128 for passwords) and ignore control keys.                                                                                                                                                                                                                                    |
| Double submit by double click                                          | Button locks while a request is open, and a second Enter sends nothing (tested).                                                                                                                                                                                                                                            |
| Late answer acting on the wrong screen                                 | An answer that arrives after you left the screen is ignored for login, leaderboard and dashboard.                                                                                                                                                                                                                           |
| Late save answer causing a second save                                 | The waiting run is cleared even when the answer arrives after you left the game over screen (tested).                                                                                                                                                                                                                       |
| Malformed server data crashing the game                                | Board data and login answers are checked for shape before use (tested).                                                                                                                                                                                                                                                     |
| Disk error crashing login                                              | Login keeps you logged in for the session even if the file cannot be written (tested).                                                                                                                                                                                                                                      |
| Password lingering in the text box                                     | The password box is emptied the moment the request is sent.                                                                                                                                                                                                                                                                 |
| One player's unsaved run saved for another                             | Log out clears the waiting run.                                                                                                                                                                                                                                                                                             |
| Unsaved or guest runs counted                                          | Guest runs are never sent. Leaving a round with Escape sends nothing.                                                                                                                                                                                                                                                       |
| Expired token mid game                                                 | Run is kept in memory, you are asked to log in, and it is saved after login.                                                                                                                                                                                                                                                |
| Two accounts showing the same name                                     | New usernames are capped at 20 characters in the register box (the leaderboard cuts at 20). Not enforced on the server yet, see B8.                                                                                                                                                                                         |
| Detailed error pages leaking code and settings (was B1)                | `DEBUG` is off unless `DEBUG=1` is set. Only your own computer sets it. Checked live: an unknown address returns a plain "Not Found" page.                                                                                                                                                                                  |
| Fake website names accepted (Host header attack)                       | `ALLOWED_HOSTS` comes from the environment and defaults to localhost. A request with a foreign name gets 400 (checked live).                                                                                                                                                                                                |
| No HTTPS (was B2)                                                      | Render serves the API over HTTPS, Cloudflare serves the landing page over HTTPS. The game refuses plain http to a real server. Django trusts Render's `X-Forwarded-Proto` header to know a request was secure. This is safe because only Render's front door can reach the server.                                          |
| Admin cookies readable over http, no HSTS (was B3)                     | `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` and one year HSTS are on when debug is off (tested, and seen in live response headers: `Secure`, `SameSite=Lax`, `strict-transport-security`).                                                                                                                                |
| Admin login form forged from another website                           | `CSRF_TRUSTED_ORIGINS` lists only the real https address. Checked live: the real origin is accepted, a foreign origin gets 403.                                                                                                                                                                                             |
| Any website reading the API from a browser (was B4)                    | CORS allows only the landing page address, only GET, no cookies, no wildcard. A foreign origin gets no permission and a browser POST from the landing page is refused (4 tests, one proven by changing the code and watching the test fail).                                                                                |
| Script injection through player names on the landing page              | Names are placed with `textContent`, never as HTML. Tested in a real browser with the name `<img src=x onerror=...>`: it showed as text and nothing ran.                                                                                                                                                                    |
| Injected scripts or foreign requests on the landing page               | Content Security Policy: scripts and styles only from the site itself, requests only to the API address, nothing else. Also `nosniff`, no referrer, frame blocking (clickjacking). Tested in a real browser under the same policy: no violations.                                                                           |
| Database connection not encrypted                                      | `sslmode=require` from the address reaches the driver through `OPTIONS` (tested). Neon enforces it.                                                                                                                                                                                                                         |
| Dropped database connections after Neon sleeps                         | `pool_pre_ping` tests a connection before using it.                                                                                                                                                                                                                                                                         |
| Redis wiped on every Render restart                                    | The server rebuilds the leaderboard from PostgreSQL at startup (tested).                                                                                                                                                                                                                                                    |
| Game fails against a sleeping free server                              | Game timeout raised to 70 seconds (background thread, window never freezes) and a wake up request is sent at launch. The landing page waits up to 90 seconds and says why.                                                                                                                                                  |
| Untested code going live                                               | Render auto deploy is set to "After CI Checks Pass".                                                                                                                                                                                                                                                                        |
| Secrets inside the Docker image or repo                                | Real values exist only in Render's environment. The image build uses dummy values. A history check (`git log --all -- server/.env`) confirms that no secret file was ever committed.                                                                                                                                        |
| Leaked `JWT_SECRET`                                                    | Rotation procedure: change the value in Render, everyone logs in again once.                                                                                                                                                                                                                                                |
| Accounts holding the secrets                                           | Two factor login is required on GitHub, Render, Neon and Cloudflare (set in the account settings).                                                                                                                                                                                                                          |
| Weak admin password online                                             | The admin account is created on the online database with a long unique password. Partly covers B5.                                                                                                                                                                                                                          |
| Django deployment check (`check --deploy`)                             | Run on the production settings. Remaining items are accepted on purpose: W008 (HTTPS redirect, Render already redirects http to https at its front door, and the game refuses http), W005 and W021 (subdomain and preload HSTS options, wrong for a shared `onrender.com` address), mail.E001 (the project sends no email). |
| Unsigned exe, SmartScreen warning, no proof the file is mine (was B13) | A SHA256 checksum file is built in the release job and published next to the exe. The landing page explains the warning and the `certutil` check. Signing itself costs money and is not done.                                                                                                                               |
| Fake or tampered release                                               | Releases are created only by the release workflow, which runs only on tags starting with `v`, and only the repo owner can push tags. The job has `contents: write` and nothing else. No third party action, only GitHub's own `gh` tool.                                                                                    |
| Broken or untested exe published                                       | The release job runs all game tests first, then starts the built exe and fails if it closes by itself. Also built and started here on Linux with the same options as a check.                                                                                                                                               |
| Secrets inside the exe                                                 | The exe holds only the public server address, taken from the repo variable `ARENA_API_URL`. `JWT_SECRET`, `SECRET_KEY` and database addresses are never in the client. The job fails if the variable is missing, so a local address is never shipped.                                                                       |
| Game writing next to the exe or into a read only place                 | Highscore and login token live in one folder, `%LOCALAPPDATA%\DecaDome`. A onefile exe unpacks to a temporary folder that is deleted on exit, so files saved there would be lost.                                                                                                                                           |
| Login token synced to other computers                                  | The token moved from `%APPDATA%` (Roaming, can follow a work account to other PCs) to `%LOCALAPPDATA%`, which stays on this PC. Old Roaming files are simply ignored (you log in once).                                                                                                                                     |
| Build tool changing under us                                           | `pyinstaller==6.22.3` is pinned in the release job.                                                                                                                                                                                                                                                                         |

## Part B: Not covered yet

Verdict columns: Possible = can be done with free tools. Necessary = needed for this project to be safe to publish.

| B5  | Admin page at `/admin/` is public. Anyone can try passwords on it. Rest optional.     | Optional. Not done yet.                                                                           |
| B6  | No limit on wrong login attempts, so a script can guess passwords. Same for register spam. | B8  | Server does not enforce the 20 character username limit.
